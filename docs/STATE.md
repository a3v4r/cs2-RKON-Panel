  - Логика в `src/lib/vanilla.ts`, интерфейс в `src/components/server/vanilla-match.tsx`.
  - Правила 5на5 MR12 и 2на2 MR8 отправляются по RCON пачками cvar.
  - Ножевой раунд, после него «Остаться» или «Сменить стороны».
  - Откат раунда через `mp_backup_restore_load_file`.
- **Обзор.** «Форс-старт» (`css_start`), переключатель ножевого раунда (`css_roundknife`, состояние берётся из ответа сервера), средний пинг по графику.

## Matchdesk.exe (`v0.9.0`)

- Релиз - один файл `Matchdesk.exe` (~115 МБ) и для запуска без exe `matchdesk-<версия>-app.zip` (папка standalone). Собирает `npm run exe` (`scripts/build-exe.mjs`): Node.js single executable application через встроенный `node --build-sea` (Node 25.5+, CI на Node 26), внутри - Node, `launcher/main.cjs` и панель архивом (asset `app.zip`, `build.txt` = версия + BUILD_ID).
- `launcher/main.cjs` (только встроенные модули):
  - без аргументов: распаковывает панель в `app\` рядом с exe, если там другая сборка (`app\.build`); `matchdesk.ini` с портом и паролем `admin`; предлагает Visual C++ Redistributable и правила брандмауэра (по 15 с на ответ, по умолчанию «да», права администратора через `Start-Process -Verb RunAs`); печатает адреса и запускает панель дочерним процессом, после падения - снова через 5 с;
  - `--run-script <файл>`: запускает файл панели (`app\server.js`, сайт скинов `app\skins-site\server.mjs`); ESM грузится через `app\matchdesk-run.cjs`, потому что сам exe не умеет `import()`;
  - `--firewall` (с правами администратора): правила «Matchdesk» для самого exe (панель и сайт) и «Matchdesk CS2 Server» для `cs2.exe` из папки CS2 панели.
- Панель знает, что запущена из exe, по `MATCHDESK_EXE=1`: сайт скинов запускается как `Matchdesk.exe --run-script ...`, в окне «Установить/Обновить CS2» есть строка «Брандмауэр» с кнопкой «Разрешить» (`src/server/firewall.ts`, проверка через `netsh ... show rule`, раз в 10 с).
- «Установить CS2»: если steamcmd нет, панель качает его с Valve; перед первой установкой проверяет 85 ГБ свободного места. Обновление не блокирует открытый на этом ПК клиент CS2.
- Вкладка «Плагины» предупреждает, если нет Visual C++ Redistributable x64.
- Exe не подписан: при первом запуске SmartScreen, «Подробнее → Выполнить в любом случае». Иконка - стандартная от Node.
- Проверено 2026-11-22 сборкой из worktree: распаковка, пароли, вопрос про брандмауэр (ответ «нет»), панель и сайт скинов через exe (вход и картинки), перезапуск панели после её завершения. Правила брандмауэра в тестах не добавлялись. Установка CS2 с нуля проверялась в `v0.8.0` (steamcmd скачался, CS2 начал качаться).

## ИИ-агент (вкладка «Агент», с 2026-11-22, релиз `v0.12.0`)

- `src/server/agent.ts`: OpenAI-совместимый `/chat/completions` через обычный `fetch`, без SDK и новых зависимостей. По умолчанию OpenRouter (`https://openrouter.ai/api/v1`), пресеты DeepSeek и Ollama. Настройки `agent { baseUrl, apiKey, model }` в `settings.json`; ключ в браузер не отдаётся, `-` в поле ключа стирает его.
- Инструменты на чтение выполняются сразу: `list_servers`, `server_status` (A2S + процесс + матч из live), `list_players`, `recent_chat`, `read_log` (консоль сервера, log-all, WeaponPaints, MatchZy), `plugins_status`, `audit_log`. Действия `rcon` и `server_process` возвращаются как `pending` и выполняются только после «Выполнить» (`decisions` в следующем запросе); в журнал пишутся как `agent rcon #id: ...`. Новый вопрос вместо решения отменяет ожидающие действия.
- `panel_api` (с 2026-11-22): любой маршрут API панели, список с телами запросов - в описании инструмента (`PANEL_API` в `agent.ts`). GET выполняется сразу, POST / PUT / DELETE - после «Выполнить»; вызов идёт на `http://127.0.0.1:PORT` с cookie сессии того, кто спросил, в журнал пишется `agent api <метод> <путь>`. Закрыты `/api/agent`, `/api/login`, `/api/logout` и маршруты, которые вызывают игровые серверы. При новом маршруте в панели дописывать его в `PANEL_API`. Проверено с DeepSeek: кнопка в быстрые действия по описанию «бесконечные деньги на разминке» (команды модель подобрала сама), чтение `/api/commands` с паролем на панели.
- Ожидание фоновых задач: инструмент `wait` (до 60 с), до 30 вызовов модели за ход. Выбранный справа сверху сервер (переключатель есть и на вкладке «Агент») уходит с каждым ходом (`selectedServerId`) и считается сервером по умолчанию. Если параметров не хватает, агент берёт значения по умолчанию и сразу предлагает действие (новый сервер: managed, competitive, de_mirage, 12 слотов, порт на 10 больше занятых, GOTV = порт + 5).
- Сценарий «Установи все плагины, создай сервер и запусти его» с DeepSeek пройден 2026-11-22 за 34 с и три подтверждения: плагины уже стояли, сервер #2 создан (после ошибки порта сам взял свободный), запущен и проверен; потом удалён.
- Номера серверов переиспользуются (новый = максимальный + 1), поэтому при удалении и создании сервера панель стирает его живой матч, чат и историю входов (`src/server/forget-server.ts`). До этого новый сервер получал старый матч удалённого.
- Откат раунда через агента (2026-11-23): правила в подсказке агента (бэкап NN = начало раунда NN+1, «откати 1 раунд» = предпоследний бэкап, «переиграй текущий» = последний), карточка подтверждения пишет «к началу раунда N». Проверено на матче 9001, загруженном через `/api/matches/config`: агент прочитал бэкапы, откатил к началу раунда 1, MatchZy встал на паузу. Несколько раундов сыграть не удалось: боты в загруженный матч не заходят, а без игроков CS2 не крутит время раунда.
- Матч без конфига (игроки пишут `.ready` или судья `css_start`): MatchZy пишет бэкапы раундов и для него, но в оригинале `get5_status` отвечает `none` без matchid, и панель (вкладка «Матч» и агент) бэкапов не видела. В форке MatchZy (2026-11-23, `G5API.cs`) такой матч отдаёт своё состояние, matchid, номер раунда и счёт команд. Проверено на матче 9003 с ботами (`css_start` без ножевого): панель показала бэкап раунда 0, откат через `/api/servers/1/restore` выполнился, матч встал на паузу. Нужен релиз форка, пока не выпущен.
- Агент только для общего аккаунта `admin`: `/api/agent` отвечает личным аккаунтам 403, пункт меню им не показывается.
- Шаги видны по ходу: чат шлёт `stream: true`, `/api/agent` отвечает NDJSON (`{type: message}` на каждое новое сообщение, в конце `{type: done, messages, pending}` или `{type: error}`); без `stream` ответ JSON целиком, как раньше. Идущий шаг в чате со спиннером («выполняется...», для `wait` - «Жду N с»), «Думает...» - только пока ждём модель.
- Разговор хранится в браузере (`localStorage`, `matchdesk-agent-chat`) и целиком отправляется каждый ход; до 10 вызовов модели за ход.
- Проверено на заглушке модели (вопрос, чтение, подтверждение, отмена, новый вопрос вместо решения) и 2026-11-22 с DeepSeek (`https://api.deepseek.com/v1`, `deepseek-chat`): ответ за 4 с с тремя инструментами, `say` после подтверждения дошёл в чат сервера и в журнал. Пользователь платит в OpenRouter киргизской картой; из РФ OpenRouter сам открывается, но российские платежи не принимает.

## Как тестировать

- Запуск: `npm run dev` (порт 3000).
- Управление сервером через API:
  - запуск: `POST /api/servers/1/process {"action":"start"}`;
  - команды RCON: `POST /api/servers/1/rcon {"command": "..."}`.
- Лог сервера: `C:\cs2server\cs2\game\csgo\console_server1.log`.
- Тестовый матч с ботами: `bot_quota 4`. Чтобы проверить режим Vanilla, MatchZy на сервере выгружают.
- После теста: остановить сервер и удалить `*_round*.txt` из `game\csgo`.

## Что выяснили про CS2 1.42

- **Бэкапы раундов.** `mp_backup_round_file` принимает только путь относительно `csgo`, абсолютный путь отклоняется (`Rejecting round backup file path`). Файл `backup_roundNN.txt` хранит состояние на начало раунда NN+1.
- **Смена сторон.** `mp_swapteams` меняет местами и игроков, и `mp_teamname_1/2`.
- **Ответы RCON.** Из-за `sv_logecho` в них попадают строки лога вида `L dd/mm/yyyy …`, их нужно отфильтровывать.
- **Молчащие команды.** `css_settings` и `matchzy_knife_enabled_default` по RCON ничего не возвращают. Узнать, включён ли ножевой раунд, можно только переключив его.
